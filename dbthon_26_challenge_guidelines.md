# DBTHON 26 - Database Systems Hackathon

## Objective
To develop an innovative database system for solving a real-world problem in a domain of your choice.

### Requirements
Your solution must:
- **a)** Identify a specific real-world problem involving data management;
- **b)** Design an appropriate database schema/model;
- **c)** Implement database operations using suitable DBMS technologies;
- **d)** Incorporate at least one meaningful database innovation;
- **e)** Demonstrate appropriate SQL queries, constraints, transactions, indexing, security mechanisms, or other relevant DBMS concepts;
- **f)** Evaluate the proposed solution using suitable performance, accuracy, scalability, security, or data-quality metrics.

The solution should demonstrate a clear relationship between the **problem**, **database design**, **innovation**, **implementation**, and **measurable outcome**.

Describe your proposed solution by explaining:
1. The existing approach used to address the problem
2. Its key limitations
3. The innovation you are proposing to overcome those limitations
4. How the innovation will be technically implemented using database concepts or technologies

## Novelty Requirement

The project must contain a feature, mechanism, architecture, algorithm, or integration that is **meaningfully different** from a conventional database implementation. Simply using a modern technology does not automatically constitute novelty.

Students should clearly establish:
1. **Existing Approach**
2. **Limitation**
3. **Proposed Approach**
4. **Novel Component**
5. **Measurable Benefit**

---

## Example Case

- **Domain:** Agriculture
- **Problem:** Large volumes of IoT sensor data make continuous monitoring inefficient.
- **Existing Limitation:** Conventional systems periodically query stored sensor records, resulting in delayed detection.
- **Innovation:** Real-time database-level anomaly detection.
- **Novelty:** Integrating continuous stream processing with database-level anomaly detection so that abnormal sensor patterns can be identified without repeatedly scanning the complete historical dataset.
- **Validation:** Compare response latency, query processing time, and unnecessary data processing against a conventional approach.

### Novelty Evaluation Criteria
- Distinctiveness of the proposed approach
- Relevance to the identified problem
- Technical depth
- Integration with DBMS concepts
- Evidence supporting the claimed improvement
- Quality of implementation and demonstration

> Students are encouraged to develop original solutions rather than simply combining existing technologies without a clear technical purpose.
